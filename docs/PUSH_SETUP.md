# הגדרת PUSH ב־Production

מערכת ה־PUSH משתמשת ב־Web Push ובמפתחות VAPID קבועים. המפתח הפרטי נשמר רק בקובץ
`/etc/gymflow/production.env` בשרת ואסור להכניס אותו ל־Git.

## יצירת מפתחות חד־פעמית

יש ליצור זוג מפתחות פעם אחת ולשמור אותו. החלפת המפתחות בעתיד תחייב את המכשירים
להירשם מחדש להתראות.

מתוך עותק מקומי של המאגר שבו הותקנו התלויות:

```bash
pnpm exec web-push generate-vapid-keys --json
```

הפקודה מציגה `publicKey` ו־`privateKey`. אין לשלוח את הפלט בצ'אט או לשמור אותו בקובץ במאגר.

## משתני הסביבה בשרת

יש להוסיף ידנית אל `/etc/gymflow/production.env`:

```dotenv
VAPID_PUBLIC_KEY=PUBLIC_KEY_FROM_GENERATOR
VAPID_PRIVATE_KEY=PRIVATE_KEY_FROM_GENERATOR
VAPID_SUBJECT=mailto:YOUR_VALID_EMAIL
```

לאחר פריסת גרסת הקוד החדשה וטעינת משתני הסביבה מחדש, הלוג צריך לכלול:

```text
Web push reminder scheduler active
```

כאשר אחד המשתנים חסר, השרת ממשיך לעבוד ללא PUSH והלוג יציג שהשירות מושבת.

## בדיקת מכשיר

1. ב־iPhone יש להוסיף את האפליקציה למסך הבית ולפתוח אותה מהאייקון. נדרשת iOS 16.4 ומעלה.
2. נכנסים לפרופיל ומפעילים התראות PUSH.
3. מאשרים את בקשת ההרשאה של מערכת ההפעלה.
4. שומרים את הפרופיל ולוחצים על „שליחת התראת בדיקה למכשיר”.
5. בודקים שוב כשהאפליקציה סגורה.

כל מכשיר נשמר כמנוי נפרד ב־PostgreSQL. ביטול PUSH בפרופיל מוחק את מנוי המכשיר.
