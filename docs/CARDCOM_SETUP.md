# חיבור Cardcom לתשלומי BALY

## מה ממומש

- יצירת דף תשלום מאובטח באמצעות `POST /api/v11/LowProfile/Create`.
- הפניית המשתמש אל דף Cardcom במקום איסוף מספר כרטיס או CVV באתר.
- קבלת Webhook ציבורי ואימות יזום של העסקה באמצעות `POST /api/v11/LowProfile/GetLpResult`.
- אימות בצד השרת של סוג המסלול, סכום העסקה וסוג הפעולה באמצעות `ReturnValue` חתום ב־HMAC.
- הפעלת מנוי, שירות נוסף או כרטיסייה רק לאחר תשובת הצלחה מאומתת.
- מניעת רישום כפול של אותה עסקה בצד הלקוח.

## משתני סביבה

בשרת יש להגדיר כסודות, ולא בקוד או ב־Git:

- `CARDCOM_TERMINAL_NUMBER`
- `CARDCOM_API_NAME`
- `CARDCOM_API_PASSWORD` — שמור לפעולות Cardcom שדורשות אותו, כגון מסמכים או זיכויים.
- `PAYMENT_SIGNING_SECRET` — מחרוזת אקראית ארוכה לחתימת הזמנות.
- `PUBLIC_APP_URL` — כתובת האתר המלאה, כולל הנתיב `/rubigym/` בפריסת GitHub Pages.
- `PAYMENT_ALLOWED_ORIGIN` — רשימת Origins מורשים, מופרדים בפסיקים.

בבניית צד הלקוח יש להגדיר:

- `VITE_PAYMENT_API_URL` — כתובת HTTPS ציבורית של שרת התשלומים, ללא `/` בסוף.

דוגמה ללא סודות נמצאת בקובץ `.env.example`.

## פריסה

GitHub Pages מגיש קבצים סטטיים בלבד ולכן אינו יכול להחזיק את מפתחות Cardcom או לקבל Webhook. יש לפרוס את `server/index.js` בסביבת Serverless שתומכת ב־Fetch API ובמשתני סביבה, ואז להגדיר את כתובת השירות ב־`VITE_PAYMENT_API_URL` של תהליך הבנייה ב־GitHub Actions.

ה־Webhook חייב להיות כתובת HTTPS ציבורית. אין להשתמש ב־localhost.

## בדיקות לפני מעבר לייצור

1. להגדיר את פרטי מסוף הבדיקה כסודות בשרת.
2. לבצע הרשמה חדשה ולוודא שהחשבון נוצר רק לאחר חזרה מוצלחת ואימות מול Cardcom.
3. לבדוק ביטול או כישלון ולוודא שלא נוצר מנוי ולא נרשם תשלום.
4. לרכוש כל סוג מסלול וכל אחת מכרטיסיות 5, 10 ו־20 אימונים ולבדוק סכום ויתרה.
5. לשלוח Webhook כפול ולוודא שהעסקה אינה מעובדת פעמיים.
6. לפני ייצור, להעביר את המשתמשים, המנויים והתשלומים מ־localStorage למסד נתונים שרתי. במבנה הנוכחי ה־Webhook מאמת את העסקה, אך נתוני המועדון עצמם עדיין נשמרים בדפדפן ולכן המימוש מתאים לבדיקות אינטגרציה ולא לסליקה רשמית.
7. להחליף למפתחות ייצור, לסובב את מפתחות הבדיקה שנחשפו בשיחה, ולהפעיל לוגים והתראות ללא שמירת פרטי כרטיס.

## חשבוניות וזיכויים

יצירת חשבונית/קבלה אוטומטית, ביטול עסקה וזיכוי אינם מופעלים עדיין. לפני עלייה רשמית יש להגדיר עם Cardcom את סוג המסמך ופרטי העסק ולממש את פעולות המסמכים והזיכויים בצד השרת בלבד.
